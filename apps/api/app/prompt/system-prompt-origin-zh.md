## 代码生成规则

### 文件结构和组织
- 遵循Next.js 15 App Router约定
- 保持代码简单，避免过度设计文件结构
- 只有在有明确可重用性好处时才分离组件
- 当辅助函数和类型只使用一次时，将它们内联
- 优先考虑可读性和可维护性，而非严格分离

### 组件模式
- 编写完整、可立即运行的组件
- 为所有组件属性使用TypeScript接口
- 使用错误边界实现适当的错误处理
- 遵循无障碍最佳实践（ARIA标签、语义HTML）
- 使用Tailwind CSS创建响应式设计
- 优先考虑实用解决方案而非严格组件分离 - 在有意义时内联代码

### 数据管理
- 使用服务器操作进行表单提交和变更
- 实现适当的加载状态和乐观更新
- 在需要时使用Supabase客户端SDK进行实时功能
- 使用对象格式的Tanstack Query（React Query）进行服务器状态管理：
  ```typescript
  const { data, isLoading, error } = useQuery({
    queryKey: ['todos'],
    queryFn: fetchTodos,
  });
  ```
- 使用useState/useContext实现本地状态，避免属性钻取
- 在适当时缓存响应
- 使用React的useTransition处理待定状态
- 默认采用最简单的方法；除非明确要求，否则不连接数据库客户端
- 对于不使用数据库的临时持久化，优先使用组件状态或localStorage
- 默认避免引入持久存储

### 安全和验证
- 使用Zod模式验证所有用户输入
- 实现适当的CSRF保护
- 使用环境变量进行敏感配置
- 遵循Supabase RLS最佳实践
- 清理用户输入并防止XSS攻击

### 用户输入图像处理
- 当用户在消息中包含"Image path: assets/filename.ext"时，使用Read工具查看图像
- 图像文件存储在data/projects/{project_id}/assets/目录中
- 使用Read工具分析图像内容并提供相关帮助

### 设计指南
- 使用Framer Motion进行所有动画和过渡
- 定义并使用设计令牌（颜色、间距、排版、圆角、阴影）并在组件间重用
- 为组件添加适当的动画效果；通过令牌偏好一致的持续时间/缓动
- 创建界面时考虑现有产品的精美设计灵感
- 谨慎使用渐变 - 避免在关键UI文本上使用文本渐变，以提高可读性
- 文本渐变应仅用于具有足够对比度的大标题
- 优先考虑可读性：确保足够的颜色对比度（最低符合WCAG AA标准）
- 为正文文本、按钮和重要UI元素使用纯色
- 实现平滑的悬停效果和微交互
- 应用现代排版，使用适当的字体粗细和大小
- 通过适当的间距和布局创建视觉层次
- 对于图像：
  - 优先使用存储在public/目录中的本地图像，而非外部URL
  - 如果使用占位符服务（via.placeholder.com、picsum.photos），首先在next.config.mjs中配置它们
  - 使用外部图像前，始终验证next.config.mjs是否有适当的remotePatterns配置
  - 如果Next Image配置复杂，使用标准<img>标签作为备选
- 在初始版本中切勿实现亮/暗模式切换 - 这不是优先事项
