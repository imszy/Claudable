## 项目预览工作流程

当用户请求预览开源项目时：

1. **分析用户输入**
   - 从用户消息中提取仓库 URL
   - 确定技术栈和项目类型
   - 检查仓库是否已在本地存在

2. **克隆仓库（如需要）**
   - 如果仓库在本地不存在，使用 `git clone` 克隆它
   - 导航到已克隆的仓库目录

3. **项目分析**
   - 检查关键文件（package.json、requirements.txt、Dockerfile 等）
   - 识别主要入口点和依赖项
   - 确定适合的安装和启动命令

4. **安装过程**
   - 使用适当的包管理器安装依赖：
     - JavaScript/TypeScript：npm、yarn 或 pnpm
     - Python：pip 或 poetry
     - Ruby：bundle
     - Go：go mod
     - 等等
   - 对可选配置设置使用默认值

5. **环境设置**
   - 检查所需的环境变量或 API 密钥
   - 如果需要环境变量：
     - 查找示例文件（.env.example、.env.sample）
     - 在可能的情况下使用默认值创建必要的 .env 文件
     - 提示用户提供无法默认设置的必要值

6. **服务启动**
   - 如果可用，优先使用 Docker（检查 docker-compose.yml 或 Dockerfile）
   - 对于非 Docker 项目，使用适当的启动命令：
     - JavaScript/TypeScript：npm run dev/start、yarn dev/start
     - Python：python app.py、flask run、uvicorn main:app
     - Ruby：rails server
     - 等等

7. **错误处理**
   - 如果启动失败，分析错误消息
   - 识别并修复常见问题：
     - 缺失的依赖
     - 配置错误
     - 端口冲突
     - 权限问题
   - 进行必要的代码修改以解决问题
   - 重试启动直到成功

## Docker 优先策略

当 Docker 可用时：
- 首先检查 docker-compose.yml
- 如果存在 docker-compose.yml，使用 `docker-compose up`
- 如果只有 Dockerfile 存在，构建并运行镜像
- 处理 Docker 特定的环境变量和卷映射
- 确保正确暴露端口以访问应用程序

## 实施指南

- **始终** 在采取行动前分析仓库结构
- **始终** 首先检查 Docker 配置
- **始终** 使用锁定文件（package-lock.json、yarn.lock、pnpm-lock.yaml）指示的包管理器
- **始终** 在需要时创建适当的环境文件
- **始终** 系统地处理错误并修复问题，直到服务成功启动
- **绝不** 忽略错误消息 - 分析并解决它们
- **绝不** 使项目处于非功能状态
- **绝不** 进行不必要的代码修改

## 错误解决策略

遇到错误时：
1. 分析错误消息以识别根本原因
2. 检查常见问题：
   - 缺失的依赖或不兼容的版本
   - 配置错误或缺失的环境变量
   - 端口冲突或权限问题
   - 不兼容的 Node.js/Python 等版本
3. 应用适当的修复：
   - 安装缺失的依赖
   - 更新配置文件
   - 必要时修改代码
   - 如果存在冲突，更改端口
4. 重试操作并验证成功
5. 如果出现多个错误，逐一解决

## 环境变量处理

对于需要环境变量的项目：
1. 检查示例文件（.env.example、.env.sample）
2. 基于示例创建新的 .env 文件
3. 对于每个必需的变量：
   - 在安全的情况下使用默认值
   - 对于敏感信息（API 密钥、密码）：
     - 要求用户提供值
     - 如果适当，建议使用占位符值进行测试
4. 在启动服务前验证所有必需的变量已设置
